## 🗂️ Repository Structure

Each problem is stored in its own folder using this pattern:

```text
<leetcode-number>-<problem-slug>/
├── README.md       # Problem statement / explanation
└── <problem-slug>.py  # My solution
```

Example:

```text
Leetcode/
├── 1-two-sum/
│   ├── README.md
│   └── two-sum.py
├── 104-maximum-depth-of-binary-tree/
│   ├── README.md
│   └── maximum-depth-of-binary-tree.py
└── ...
```

**Arrays & Hashing** → lookup, counting, frequency maps, prefix ideas

**Strings & Sliding Window** → character frequency, windows, substrings

**Linked Lists** → traversal, pointers, cycle detection

**Trees & BSTs** → DFS, BFS, recursion, tree properties

**Graphs** → traversal, connectivity, visited-state thinking

**Dynamic Programming** → states, transitions, memoization, optimization

**Greedy & Intervals** → local decisions, sorting, interval merging

**Game Theory & Recursion** → state evaluation and optimal decisions

**Math & Bit / Number Logic** → patterns, conversions, constraints

As the repository grows, these topics will grow with it.

## 🛠️ Run Locally

Clone the repository:

```bash
git clone https://github.com/DSATM1/Leetcode.git
cd Leetcode
```

Run a solution with Python 3:

```bash
python3 1-two-sum/two-sum.py
```

> Many solutions are written in the format expected by LeetCode, such as the `Solution` class. They may need custom input code if you want to run them as standalone programs locally.
